# Архитектура

## Состав

Браузер → ASP.NET Core 8 → EF Core 8 → SQLite. HTML/CSS/JavaScript находятся в `backend/wwwroot` и обслуживаются тем же процессом, что и REST API. PostgreSQL, Python-сервер и отдельные серверы модулей отсутствуют. Python используется только необязательным интеграционным тестом.

`Data` содержит общие сущности, конфигурацию связей и начальное заполнение. `Modules/Personnel` - сотрудники; `Siz` - жизненный цикл изделий; `Operations` - НФГО, сооружения, эвакуация и режим; `Training` и `Wartime` - адаптированные сервисы ZIP; `Reports` - расчеты и экспорты. `Common` содержит валидацию, вход оператора, справочники и маркировку.

## Общие данные

Сотрудник имеет один ID и уникальный табельный номер. Назначения в НФГО, учебную группу, транспорт, пункт приема и укрытие ссылаются на этот ID. Импорт хранит пару «источник + исходный ID»; ФИО не используется как ключ объединения.

Тип СИЗ хранит цену, норму на сотрудника, срок поставки, хранения и класс отходов. Партия содержит паспортные сведения и срок годности. Каждая физическая единица представлена карточкой. Строки выдачи, списания и утилизации относятся к тем же карточкам. Ведомость сохраняет снимок имени и табельного номера получателя.

Связи SQLite проверяются через внешние ключи; удаление связанных записей ограничено. Режим WAL позволяет читать данные во время записи. Все запросы изменения последовательно проходят через общую блокировку в одном процессе; проверка состояния и `SaveChanges` защищены от одновременной повторной выдачи. Несколько серверных процессов с одной базой не поддерживаются.

## Переходы и запреты

- Проект выдачи не меняет остатки. Подтверждение повторно проверяет годность, размер, подразделение и наличие, затем переводит карточки со склада на сотрудника. Подтвержденный документ не редактируется.
- Проект списания разрешен для просроченного или негодного изделия. Подписание переводит карточки в «Списано». Передача подходящему контрагенту переводит их в «Утилизировано»; повторная операция запрещена.
- Подписанное занятие заблокировано. Исправление требует согласованной заявки; после изменения занятие подписывается заново. Прогресс учитывает подписанные занятия. Отпуска и больничные по датам не позволяют отметить присутствие.
- Приказ НФГО содержит снимок состава. Изменение состава до подписания требует обновления проекта. После подписания снимок неизменяем.
- Переход режима требует подписанного приказа и наступившего времени с часовым поясом. Одной операцией сохраняются режим, ограничения, сменные графики, приостановка обычных отпусков и внутренние уведомления. Декретные отсутствия не приостанавливаются.

## Расчеты

Готовность звена - минимум укомплектованности, оснащения и обученности, ограниченный 100%. Годовая обученность сотрудника требует 15 часов и зачета; порог протокола 12 часов хранится отдельно. Финальная выгрузка НФГО блокируется при вакансиях. При отсутствии норм оснащения готовность по оснащению равна нулю.

План строится на пять последовательных лет. Для каждого типа и размера учитываются действующие карточки, выбытие по сроку, потребность сотрудников и расчетные будущие закупки. Поэтому один дефицит не начисляется повторно каждый год. Цены и сроки редактируются в справочнике типов. Нормы НФГО учитываются непосредственно для имущества без размеров; распределение повышенных норм НФГО по размерам остается ограничением расчета.

## Доступ, хранение, развитие

Cookie-вход с HttpOnly/SameSite Strict защищает все служебные API, чтение и запись. Изменения, включая вход и multipart, проверяют CSRF-токен. Есть ограничение неверных попыток и отзыв сессии при выходе. В серверном режиме cookie имеет Secure, forwarded-заголовки принимаются только от явно заданного прокси. Сервер по умолчанию слушает loopback. Это один оператор, без внешнего провайдера идентификации. Общий аудит не редактируется API и защищен от изменения через контекст EF; прямой доступ к файлу базы не защищен криптографически.

База создается и обновляется последовательными SQL-миграциями. Версии с контрольными суммами хранятся в `__GochsMigrations`. Прежняя схема проверяется по исходному SQL перед регистрацией базовой версии; обновление выполняется в транзакции после резервного копирования. Неизвестная схема останавливает запуск. Файл блокировки исключает второй сервер на той же базе. Файлы вложений хранятся в SQLite, до 10 МБ каждый. Проверяются расширение, MIME-тип, сигнатура и ограничение размера. Списки возвращают только метаданные, скачивание требует входа. Антивирусная проверка не подключена.

Учебные формы не заменяют утвержденные регламентом организации документы. Подключение УКЭП, адресных рассылок, 1С, ролевой модели и промышленного резервирования требует отдельной интеграции.

Время приказов хранится в UTC и восстанавливается из SQLite с явным DateTimeKind.Utc. DTO требует смещение часового пояса. Интерфейс и документы используют Europe/Moscow, независимо от зоны браузера и сервера.
