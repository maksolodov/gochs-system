# Тестирование и отладка (этап 4)

В этой папке собраны материалы для проверки объединенной информационной системы ГО и ЧС.

- [План тестирования](TEST_PLAN.md) - что и как проверяется.
- [Тест-кейсы](TEST_CASES.md) - действия и ожидаемые результаты.
- [Приемочный чек-лист](ACCEPTANCE_CHECKLIST.md) - краткая ручная проверка.
- [Нагрузочное тестирование](LOAD_TEST.md) - режимы нагрузки и запуск скрипта.
- [Шаблон отчета о тестировании](TEST_REPORT.md) - фиксация фактических результатов.
- [Шаблон сообщения о дефекте](BUG_REPORT.md) - описание найденной ошибки.

Автоматизированные проверки находятся в корневом каталоге `tests`:

- [`tests/integration.py`](../../tests/integration.py) - интеграционные API-проверки и короткий нагрузочный прогон.
- [`tests/ui.cjs`](../../tests/ui.cjs) - проверка интерфейса через Playwright.
- [`tests/load_test.py`](../../tests/load_test.py) - отдельные нагрузочные прогоны с измерением времени ответа.

Материалы содержат **план и ожидаемые результаты**, а не утверждения об успешной сдаче тестов. Фактический статус и найденные дефекты заполняются после выполнения проверок в [отчете](TEST_REPORT.md). Чистый запуск тестов использует отдельную временную базу, если это предусмотрено самим скриптом. Ручные проверки изменяют данные текущего стенда: используйте тестовую базу.

Объем этапа 4 взят из исходного задания: модульное, интеграционное, нагрузочное и пользовательское тестирование, проверка взаимодействия модулей и исправление выявленных ошибок. Для unit-тестов отдельного автоматизированного проекта пока нет, поэтому их выполнение не заявляется.
