# Тест-кейсы ГОЧС

Проверки подготовлены для объединенной системы (модули 6-19) и заменяют тест-кейсы старого API из первоначального архива этапа 4.

**Состояние:** все кейсы имеют статус `NOT RUN` до их фактического выполнения. Автоматизированные проверки в `tests/integration.py` и `tests/ui.cjs` пересекаются с частью кейсов, но без лога прогона статус не изменяется.

**Предусловия:** работающий тестовый стенд, вход под оператором, демонстрационные данные в SQLite, резервная копия перед операциями удаления, подписания, утилизации или смены режима. Записи, создаваемые для кейсов, должны иметь уникальные номера.

**Порядок:** сначала общие, сотрудники, учет имущества, НФГО и обучение; активацию военного режима выполнить последней, поскольку состояние сохраняется в базе.

Для отметки результатов скопируйте нужные строки в заполненный отчет, замените `NOT RUN` на `PASS`, `FAIL` или `BLOCKED`, приложите скриншот или лог при необходимости.

## Отдельные замечания

- Кейсы `UNIT-01..UNIT-05` представляют **план unit-проверок**, а не существующие исполняемые unit-тесты.
- Кейсы `LOAD-01..LOAD-03` должны выполняться против локального стенда с реальной авторизацией, см. `LOAD_TEST.md`.
- Сценарии утилизации и перевода режима меняют состояние данных и не должны выполняться на общей демонстрационной базе без подготовки.
- Соответствие реальной нормативной форме МЧС и юридической силе электронной подписи не проверяется: в проекте используются учебные формы и подписи.
