# Руководство пользователя системы ГОЧС

## 1. Назначение

Руководство предназначено для оператора, который ведёт данные по ГО и ЧС через web-интерфейс.

Система объединяет:

- сотрудников;
- СИЗ;
- НФГО;
- защитные сооружения;
- эвакуацию;
- обучение;
- приказы;
- отчёты;
- план закупок;
- специальный режим;
- уведомления и аудит.

> Текущая версия использует одну операторскую модель доступа. Термины «оператор», «руководитель», «кладовщик» в документации обозначают организационную ответственность, а не отдельные роли доступа в приложении.

## 2. Вход

Откройте адрес, выданный администратором.

При локальном запуске по умолчанию:

```text
http://127.0.0.1:5080
```

Введите:

- имя оператора;
- пароль.

После нескольких неправильных попыток система временно блокирует новые попытки с этого адреса. Не пытайтесь многократно подбирать пароль — обратитесь к администратору.

## 4. Главная

Главная страница показывает:

- сотрудников;
- СИЗ на складе;
- выданные СИЗ;
- средний прогресс мероприятий;
- изделия с истекающим сроком;
- состояние эвакуации;
- выполнение годовой подготовки;
- текущий режим.

Используйте Dashboard как оперативную сводку, а не как замену профильных разделов.

## 5. Сотрудники

Общий справочник сотрудников используется всеми модулями.

У сотрудника могут храниться:

- табельный номер;
- ФИО;
- подразделение;
- должность;
- кадровый статус;
- размер противогаза;
- размер костюма;
- смена;
- учебная группа;
- звено и роль НФГО;
- защитное сооружение;
- транспорт;
- пункт приёма;
- признак эвакуации;
- необходимость помощи;
- резервирование;
- обучение в УМЦ.

### Основные ограничения

- табельный номер уникален;
- нельзя переполнить звено НФГО;
- нельзя назначить человека в непригодное укрытие;
- нельзя превысить вместимость укрытия;
- нельзя использовать недоступный транспорт;
- нельзя превысить вместимость транспорта и пункта приёма;
- учебную группу нельзя произвольно менять при наличии истории посещаемости;
- в активном специальном режиме обычный отпуск может быть запрещён.

## 6. Реестр СИЗ

### 6.1 Типы

Тип СИЗ содержит:

- наименование;
- категорию;
- цену;
- срок поставки;
- срок хранения;
- норму на сотрудника;
- класс отходов.

Эти данные влияют на выдачу, готовность и план закупок.

### 6.2 Склады

Хранят наименование и адрес места хранения.

### 6.3 Приход партии

В разделе **Реестр СИЗ** нажмите **Принять партию**.

Заполняются тип, склад, номер партии, производитель, размер, место хранения, даты, сертификат, количество и префикс инвентарных номеров.

После сохранения система создаёт отдельную карточку каждой физической единицы.

Пример:

```text
GP7-0001
GP7-0002
GP7-0003
```

Проверяются количество, тип, склад, даты, уникальность партии и инвентарных номеров.

## 7. Карточки СИЗ

Каждая физическая единица имеет карточку.

Статусы:

```text
InStock      — на складе
Issued       — выдано
WrittenOff   — списано
Disposed     — утилизировано
```

Состояния:

```text
Fit          — годно
Unfit        — негодно
Inspection   — на проверке
```

Для карточки доступен штрихкод Code 39.

Списанное или утилизированное изделие нельзя вернуть в обычный цикл простой сменой состояния.

## 8. Выдача СИЗ

Сценарий:

```text
Проект ведомости
→ проверка
→ подтверждение
→ фактическая выдача
```

### Ручная выдача

Оператор выбирает сотрудников и карточки.

Система проверяет:

- сотрудник не уволен;
- подразделение соответствует ведомости;
- изделие находится на складе;
- изделие годно;
- срок не истёк;
- размер соответствует сотруднику;
- одна карточка не выбрана дважды.

### Автоматическая выдача

Укажите подразделение, тип СИЗ и основание.

Система подбирает годное имущество нужного размера всем действующим сотрудникам подразделения.

Если хотя бы одному сотруднику подходящего изделия не хватает, ведомость не создаётся частично.

### Подтверждение

До подтверждения остатки не изменяются.

После подтверждения:

```text
IssueStatement = Confirmed
SizCard = Issued
```

Сохраняются получатель и дата выдачи.

Строка ведомости хранит снимок ФИО, табельного номера, наименования, партии и размера.

Подтверждённую ведомость редактировать нельзя.

> Запись ФИО подписанта не является УКЭП.

## 9. Списание

Списание разрешено для изделия, которое:

- просрочено; или
- имеет состояние `Unfit`.

Порядок:

1. выбрать кандидатов;
2. создать проект акта;
3. указать комиссию и причину;
4. проверить;
5. подписать.

После подписания:

```text
Status = WrittenOff
Condition = Unfit
```

## 10. Утилизация

Утилизация возможна только после подписанного списания.

Указываются контрагент, договор, документ передачи, дата и способ.

Проверяются:

- подписанный акт;
- даты;
- срок лицензии;
- соответствие класса отходов;
- отсутствие повторной утилизации.

Результат:

```text
WrittenOff → Disposed
```

## 11. НФГО

Раздел объединяет:

- формирования;
- звенья;
- состав;
- нормы оснащения;
- резерв имущества;
- внутренние оповещения.

У звена есть штатная вместимость. Нельзя сделать её меньше уже назначенного состава.

Норма оснащения связывает:

```text
звено + тип СИЗ + требуемое количество
```

Конкретную карточку можно зарезервировать за звеном только со склада.

Учебный сбор создаёт внутренние уведомления действующим сотрудникам звена.

## 12. Готовность НФГО

Готовность определяется как минимум из:

- укомплектованности;
- оснащения;
- обученности.

Например:

```text
личный состав 100%
оснащение      80%
обучение       60%
готовность     60%
```

При отсутствии норм оснащения показатель оснащения считается нулевым.

## 13. Защитные сооружения

Карточка содержит:

- регистрационный номер;
- наименование;
- класс защиты;
- адрес;
- вместимость;
- состояние;
- ответственное лицо;
- следующую проверку.

Состояния:

```text
Ready
Limited
Unfit
```

Ограничения:

- нельзя уменьшить вместимость ниже числа назначенных сотрудников;
- нельзя признать сооружение `Unfit`, пока люди не перераспределены;
- нельзя назначить сотрудника в `Unfit`;
- нельзя превысить вместимость.

## 14. Проверки сооружений

Проверка содержит:

- дату;
- проверяющего;
- результат;
- исправность ФВУ;
- герметичность дверей;
- замечания;
- следующую дату.

Нельзя:

- проводить фактическую проверку будущей датой;
- указывать следующую дату не позже текущей;
- ставить `Ready` при неисправной ФВУ или негерметичных дверях;
- ставить `Unfit`, пока внутри назначены сотрудники.

Результат проверки обновляет текущее состояние сооружения.

## 15. Эвакуация

Модуль содержит:

- транспорт;
- пункты приёма;
- маршруты;
- распределение сотрудников;
- автоматический план.

Транспорт учитывает вместимость, готовность, водителя и договорные реквизиты.

Автоплан:

1. выбирает действующих сотрудников, подлежащих эвакуации;
2. ставит выше людей, которым нужна помощь;
3. назначает доступный транспорт;
4. назначает пункт приёма.

Сводка показывает:

- всего;
- подлежащих эвакуации;
- распределённых;
- места;
- дефицит;
- расчётное число волн;
- вместимость пунктов;
- нераспределённых.

Это распределение по вместимостям, а не GIS-оптимизация маршрутов.

## 16. Журнал занятий

### Занятие

Хранятся тема, номер, дата, время, часы, вид, место и руководитель.

Год занятия должен совпадать с годом группы.

### Посещаемость

Фиксируются:

- Present / Absent / Sick;
- Passed / Failed / None;
- балл теста.

### Подписание

Будущее занятие подписать нельзя.

После подписания занятие и посещаемость блокируются для прямого редактирования.

### Исправление

Для подписанного занятия создаётся ChangeRequest.

```text
ChangeRequest
→ Approved / Rejected
```

При одобрении подпись снимается, затем запись можно исправить и подписать снова.

### Пороговые значения

- 12 часов — готовность учебного протокола;
- 15 часов + `Passed` — годовая обученность для готовности НФГО.

## 17. Приказы

### Приказ НФГО

При создании сохраняется snapshot состава.

Если состав изменился до подписи, проект нужно обновить.

После подписи snapshot неизменяем.

### Приказ режима

Статусы:

```text
Draft → Signed → Activated
```

Активация доступна только после подписи и наступления времени.

Время отображается в `Europe/Moscow`.

> Подписание в системе является учебной фиксацией ФИО и времени, не УКЭП.

## 18. Режим работы

После активации режима:

- состояние становится `Wartime`;
- включаются специальные графики;
- обычные отпуска ограничиваются;
- включаются внутренние экстренные уведомления;
- открывается защищённая сводка;
- действующие обычные отпуска приостанавливаются;
- резервированным сотрудникам создаются уведомления.

Декретные отсутствия автоматически не приостанавливаются.

## 19. План закупок

План строится на пять последовательных лет.

Учитываются:

- персонал;
- размеры;
- нормы;
- остатки;
- сроки годности;
- будущие закупки;
- цена;
- срок поставки;
- срок хранения.

Будущая закупка увеличивает расчётный остаток, поэтому один дефицит не должен повторяться каждый год.

## 20. Отчёт НФГО

Отчёт показывает:

- организацию;
- формирования;
- штат;
- состав;
- вакансии;
- оснащение;
- обучение;
- готовность;
- обеспеченность;
- подготовку.

Финальная выгрузка блокируется при наличии вакансий.

Доступны XLSX, XML, JSON и HTML/печать.

## 21. Аналитика

Раздел мероприятий хранит направление, задачу, ответственного, срок и процент выполнения.

Эти данные участвуют в общей сводке.

## 22. Уведомления

Текущий канал — внутренний `InApp`.

Можно просматривать уведомления и отмечать их прочитанными.

Внешняя e-mail/SMS доставка отсутствует.

## 23. Настройки

Настройки организации используются в новых документах и отчётах:

- название;
- категория ГО;
- руководитель.

Меняйте их только после согласования.

## 24. Вложения

Разрешены:

- PDF;
- PNG;
- JPEG.

Максимум 10 МБ.

Проверяются расширение, MIME и сигнатура файла.

Антивирусная проверка не реализована.

## 25. Документы и PDF

В зависимости от операции система формирует HTML, DOCX, XLSX, XML и JSON.

PDF сохраняется через печать HTML браузером.

Перед официальным применением формы должны быть сверены с требованиями организации.

## 26. Типичные ошибки

### 400

Некорректные данные, binding, validation или CSRF.

### 401

Нет действующей сессии. Войдите снова.

### 404

Запись не найдена.

### 409

Операция запрещена текущим состоянием.

Примеры:

```text
Подтвержденную ведомость нельзя редактировать.
Штат звена заполнен.
Сооружение непригодно.
Приказ уже подписан.
```

Исправляйте причину ограничения, а не пытайтесь обходить его ручным изменением данных.

## 27. Завершение работы

Нажмите **Выйти**, особенно на общем компьютере.

Не передавайте пароль через открытые каналы.

## 28. Что пользователь не должен делать

- редактировать SQLite вручную;
- удалять рабочий Docker volume;
- обходить бизнес-правила прямым SQL;
- считать обычную текстовую подпись УКЭП;
- менять системное время ради обхода ограничений;
- запускать второй экземпляр на той же БД;
- выполнять restore без администратора.
