# Нагрузочное тестирование

Цель - проверить устойчивость чтения служебных данных при конкурентных запросах, не изменяя записи в SQLite. Тест выполняется **только на собственном учебном стенде**, не на общедоступном сервере преподавателя.

## Подготовка

1. Запустить приложение локально и убедиться, что открывается `http://127.0.0.1:5080`.
2. Узнать пароль оператора согласно основному `README.md`.
3. Выполнять команды из корня репозитория. Скрипт попросит пароль без отображения на экране.

## Прогоны

```sh
python tests/load_test.py --requests 100 --workers 10 --output test-results/load-100.json
python tests/load_test.py --requests 500 --workers 25 --output test-results/load-500.json
python tests/load_test.py --requests 1000 --workers 50 --output test-results/load-1000.json
```

По умолчанию проверяется `GET /api/dashboard`. Для другого безопасного маршрута можно передать `--endpoint /api/employees`.

Результат включает количество успешных запросов и ошибок, HTTP-статусы, длительность, запросы в секунду, среднюю задержку, медиану, P95 и P99 (миллисекунды). Результат каждого прогона сохраняется в JSON-файл; `test-results/` исключен из Git.

При ошибках на малой нагрузке следующие прогоны не выполнять, пока не установлена причина. Не проводите нагрузочный тест против публичного чужого сервера без разрешения. Если сценарий не запускался, в отчете указывается `NOT RUN`.

## Дополнительно

В `tests/integration.py` уже есть краткая проверка на 100 GET-запросов при 8 потоках. Она не заменяет отдельные измерения на 500 и 1000 запросах и не является подтверждением устойчивости в промышленной эксплуатации.
